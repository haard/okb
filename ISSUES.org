* HIGH Severity
** DONE [#A] Database connection leak in KnowledgeBase
:PROPERTIES:
:FILE: mcp_server.py:129-134
:TYPE: Resource Leak
:END:

Connection is created but never closed. Long-running MCP/HTTP servers will exhaust database
connections.

#+begin_src python
def get_connection(self):
    if self._conn is None or self._conn.closed:
        self._conn = psycopg.connect(self.db_url, row_factory=dict_row)
        register_vector(self._conn)
    return self._conn
#+end_src

*Fix:* Use connection pooling, implement =__del__= with explicit close, or use context manager
pattern for each query.

** DONE [#A] SQL LIKE pattern injection in rescan
:PROPERTIES:
:FILE: rescan.py:137
:TYPE: Security
:END:

String concatenation =source_path + "::%"= - if path contains =%= or =_= chars, LIKE could match
unintended rows and delete wrong documents.

#+begin_src python
result = conn.execute(
    """DELETE FROM documents
       WHERE source_path = %s OR source_path LIKE %s""",
    (source_path, source_path + "::%"),
)
#+end_src

*Fix:* Escape special LIKE characters (=%= and =_=) before concatenation, or use PostgreSQL's
=escape= clause.

* MEDIUM Severity
** TODO [#B] Race condition in ingest deduplication
:PROPERTIES:
:FILE: ingest.py:1375-1415
:TYPE: Concurrency
:END:

Check-then-delete pattern without transaction lock. Between checking for existing hash and
checking for existing path, another process could modify the database.

*Impact:* Two concurrent ingests of the same file could both delete and insert, causing duplicate
entries or lost data.

*Fix:* Use a single atomic operation or explicit transaction with row locking.

** DONE [#B] No subprocess timeout in Docker operations
:PROPERTIES:
:FILE: cli.py:77-96
:TYPE: Robustness
:END:

=subprocess.run()= for Docker operations has no timeout. If Docker daemon hangs, CLI hangs
indefinitely.

*Fix:* Add =timeout=5= parameter to subprocess.run() calls.
